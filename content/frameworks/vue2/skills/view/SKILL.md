# 页面

先按基础规则定位项目 profile、一个相邻页面和实际调用入口。页面目录沿用项目，不为满足示例建立新结构。

- 页面持有查询、分页、编辑和提交状态，复用项目组件与逻辑函数；请求契约放 API 层，跨页面共享才放 Store（共享状态）。不因文件较长把整页搬进混入。
- `data()` 返回新的对象，表单当前值与重置基准不能共享可变引用；导入的配置、常量不作为可编辑状态直接修改。
- 新增对象属性用项目适用的 `$set` 或替换对象；数组索引和长度更新使用可追踪方式，例如 splice 或替换数组。不能假设直接赋值总能触发渲染。
- computed 只派生值，watch 处理需要响应变化的副作用；不在计算属性中请求接口或修改源状态。不用 deep watch 代替明确的数据流。
- 每个异步操作负责自己的 loading、失败、空数据和重复提交；最新有效请求才能提交结果、错误及结束状态。取消请求不代表服务端撤销操作。
- 请求缺失和模拟数据遵循基础规则；有真实请求时禁止失败后回退演示数据。
- 监听、定时器、观察器、上传和未决请求在 beforeDestroy/destroyed 清理；keep-alive 场景按实际要求处理 activated/deactivated，避免反复进入后重复注册。
- 交付核对当前需求涉及的成功、失败、重置、返回及实例隔离；记录复用来源、实际检查结果和待联调项。
