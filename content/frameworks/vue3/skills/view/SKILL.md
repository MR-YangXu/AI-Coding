# 页面

页面连接局部状态、展示与业务事件。读哪些文件、是否再打开其他技能，以基础规则的阅读预算为准。本技能不预设页面目录、组件库或设备类型。

## 开始前确定复用与结构

- 根据当前交互检索可用组件、组合式函数和样式能力，选用途与运行环境相近的范例。用户或项目指定了参考页面时，说明采用哪些组织方式，并核实对应能力在当前仓库存在。
- 简述复用清单与文件职责后直接实施；能力不匹配时说明具体缺口。不能因为截图中没有组件名称就从底层控件重写已有且满足需求的交互，也不能按参考仓库的 import 路径生成不存在的引用。
- 状态、逻辑、配置、类型与样式按实际职责和项目惯例组织；需要独立维护或被多个文件使用时再拆分，不为目录齐全创建文件。局部改动保持最小范围。
- 实现前明确本次交互的操作与预期结果，包括相关状态如何同步及失败时如何恢复；只选择当前任务涉及的行为，按项目已确认约定确定，不套用其他场景的验收清单。

## 边界

- 页面持有当前功能的局部交互状态，连接组件、API 与业务事件。已有组合式函数满足需求时优先调用，页面保留参数、结果适配和业务决策。
- 不要为缩短文件把整页状态抽成 Hook，或提升到全局 Store。
- 请求与原始响应契约留在 API 层；展示派生或纯转换沿用已有边界，没有既有边界时就近放在消费方，实际复用时才共享，不能改变传输契约。跨路由共享放 Store，页面私有 UI 放同域组件。
- 需要实例隔离的可变默认值使用工厂函数或项目已有克隆方式，不直接用 `reactive(共享配置对象)` 修改模块级默认值；可编辑状态与重置基准不能共享可变引用。
- 演示数据仅在交付范围允许时使用，沿用项目演示层或独立文件并限制启用范围；不让示例数据默认进入正式业务路径。

## 编排

- 请求成功前不假设返回形状；按本项目响应层级更新页面数据。
- 模板避免复杂转换和多语句事件；用户可见文案走项目国际化入口。
- 接口缺失不妨碍先建立清晰的展示和组件边界，但不能编造端点、权限、字段契约或业务计算规则；设计稿中的示例内容不能作为契约依据。

## 异步与交互

- 每项异步闭合 loading，并处理空数据、失败、重复提交和过期响应。
- 页面与子组件通过明确的输入和事件协作，只传递当前交互所需的数据。
- 进入、返回和离开页面时的状态保留与恢复遵循项目既有模式。
- 独立操作维护各自的提交状态，避免重复触发；按项目策略在成功后更新数据，失败时保留原状态或回滚乐观更新，不能用仅修改内存冒充已保存。

## 文件上传（涉及时）

- 先复用已有上传组件，按项目契约在请求前检查大小、数量及允许的文件类型，失败时明确反馈；未知限制先确认，不自行编造阈值。
- 大文件或长传沿用项目取消能力，离开页面时取消未完成的上传；取消不能被当作上传成功。

## 交付检查

静态检查和核对次数遵循基础规则的验收预算。代码里要能对上这些情况，不为单页引入测试框架或浏览器脚本：

- 状态、数据、展示和样式有明确归属，没有重写已确认可用的公共能力。
- 加载、空结果、失败、重复请求和返回该页时的状态在代码路径里闭合。
- 复用的页面、组件、API 和路由能指出位置；未确认的接口或权限不写成已实现。
- 涉及上传时，有效文件、超限或不支持的类型、失败和取消后的恢复都有分支。
- 模拟数据只证明展示和失败恢复。真实保存未验证时单独标明。
