# 常量与数据字典

本技能适用于通用前端、后台和 H5，且只在本次改动新增或修改枚举、状态字面量或数据字典时阅读。不要求页面采用后台结构。接口码值以当前契约为准，翻译键的生成方式以国际化技能的规则为准；不要为了核对再打开那两份技能。

## 统一入口与读取顺序

1. 查看 `.ai-code/config.json` 的 `constants` 路径与绑定，以及项目已有约定。配置不存在时定位实际入口；默认公共定义为 `src/constants/common.{{ext}}`，由 `src/constants/index.{{ext}}` 导出，业务定义跟随模块的 `constants.{{ext}}`。
2. **先查公共导出，再查当前业务入口，再读取相关定义和调用方。** 公共入口是转导出时追踪实际定义；找到公共候选后仍须检查当前业务是否已有对应定义或冲突。读取顺序不代表公共定义自动覆盖业务契约。
3. 优先复用当前会话中已核实且未变化的内容。文件变化、业务范围变化或上下文缺失时补读必要片段；只返回相关检索结果，不每轮全文加载目录，不建立另一份重复的常量清单。
4. 新增前按业务名称、字段、成员和字典映射定向检索全项目。已有同义定义就复用；确需新增时先确定唯一归属，再补定义与适用检查绑定。仅查询或审查时不创建文件。

## 禁止多处定义（强制）

- **同一业务语义只能有一份权威常量和一份字典映射。** 页面、组件、{{logic}}、API 和页面配置均从所属定义模块导入，不能各自声明，换名复制同样违规。
- 公共与业务不得重复维护同一含义的定义。只在语义和接口契约一致时提取公共定义；不同业务恰好使用相同数字不代表可以共用。
- 公共定义通过公共 `index.{{ext}}` 引用；业务定义从所属模块引用，不塞进公共导出入口。公共模块不反向依赖业务；跨业务共享时先确认应归属的公共领域。
- 转导出、导入别名以及由权威定义派生的只读选项或展示配置允许存在。不能把复制、展开后独立修改的对象当作第二份常量维护。
- 发现历史重复时先核对契约和调用方，再按当前任务范围迁移到唯一来源；不能仅凭同名、同值自动删除或合并。

## 定义与使用

- 业务状态、类型、渠道、固定字典标识和筛选哨兵值必须命名，即便只有一个调用方。码值仅在定义处维护，比较、赋值、默认值、请求参数、switch 分支、选项 value 和模板绑定均引用常量。
- 常量声明遵循已选择的语言规则。保持后端原始值与类型，不猜测 1、2、3 的业务意义，不混用数字与字符串。
- 字典键引用枚举成员；选项从常量和字典派生，不在 options、labels、模板里分别维护同一映射。派生数字选项时遍历常量值，避免 `Object.keys` 把数字码值变成字符串。
- 字典保持领域数据形态，UI 组件的色彩、插槽等展示配置放在调用方；常量模块不保存可变页面状态，不创建请求或组件实例。
- 计数、数组下标、一般布局数字不因出现 0 或 1 就强制提取；同样不能把已有业务码值伪装成普通数字。

## 动态字典与国际化

- 稳定业务枚举与接口动态字典区分处理。动态选项继续来自现有 API、{{logic}}或字典服务；固定字典 code 使用常量，不能将动态结果快照复制成静态枚举，也不要求把每个远端选项 ID 注册为常量。
- 国际化项目在字典保存翻译键，在响应式上下文中生成选项文案；不在模块加载时固定翻译结果。无国际化项目可以集中保存显示文案。
- 未知返回值保留其未知状态并按项目约定展示，不默认当成某个合法状态，不掩盖契约差异。

## 自动检查与验收

- 配置只记录定义归属、路径、导出名和使用绑定，不重复登记实际码值或文案。任务期间不打开安装包里的常量模板；接入检查时只改 `.ai-code/config.json` 的 `constants`。
- 通过 `ai-code check` 执行已配置模块的只读静态检查；`observe` 报告确定违规，`enforce` 阻断确定违规。改名后结构相同的定义只提示疑似重复，须核对语义；自动识别的边界不放宽禁止同义重复定义的规则。
- 未配置和检查未完成不能写成通过。程序扫描不需要模型全文读取源码；先看诊断摘要，只补读问题位置。现有 `quality inspect` 仍用于项目 ESLint 增量诊断。
- 验收公共与业务读取依据、导入来源、重复定义、字典完整性、码值类型及选项提交值；涉及国际化时验证语言切换，动态字典验证加载与未知值展示。自动测试不能证明模型每次都执行了检索顺序。
