# 组件

先看相邻组件、调用方和已有组件库。新组件沿用相邻 SFC 写法；相邻已是 `<script setup>` 时用 `<script setup lang="ts">`（项目无 TS 则不加 `lang="ts"`）。数据流先于复用；涉及页面查询、共享状态或独立异步流程时，同时读取对应技能。

## 边界与放置

- 先评估已有组件的输入、插槽、事件、主题和交互能力，满足当前需求时复用；不匹配时说明差异，再决定扩展或新建。
- 页面专用组件放在所属功能附近，沿用项目已有目录。一个区域具有独立展示、交互和样式职责，或需要复用结构时，优先提取为私有组件；少量纯布局标签不必拆分。
- 仅当 ≥2 个不同业务模块需要同一交互外壳、且不依赖具体业务 API 或路由时，才抽到项目既有共享目录。优先扩展已有组件。
- 外观相似但业务规则或请求不同时，保留各自业务包装，仅共享纯交互外壳；外壳通过输入、插槽与事件连接调用方，不接收业务 API 地址或权限键。

## 契约与数据流

- 结构用插槽（需向父级透传项状态时用作用域插槽），动作用语义事件，独立设置用 Props。
- 数据向下传，事件或 `v-model` 向上通知；不要修改传入对象字段。
- Vue 3.4+ 使用 `defineModel`，更早版本使用 `modelValue` 与 `update:modelValue`。
- Prop 仅作初始值时须注明后续更新不同步；需要实时同步则用 `computed`。
- 多根节点必须把 `$attrs` 绑到实际目标元素。
- 需要被父组件命令式调用的方法（如 `validate()`）须 `defineExpose`；能用 `v-model` 或事件完成的不要改成 ref 调用。
- TypeScript 项目明确 Props 和事件载荷的类型，确保调用方能检查输入与输出；业务专用字段以当前组件契约为准。

## 状态与副作用

- 基础 UI 组件可有开合等展示状态，但禁止请求业务 API、禁止读取业务 Store。
- 业务组件可处理 API 请求，必须向调用方暴露 `loading`、`error` 及结果事件。
- 处理重复触发、过期响应、失败与卸载清理。不要仅为缩短文件而抽取 composable。

## 样式与内容（涉及时）

- 沿用项目已有 CSS、Less、SCSS 或其他样式方案，复用主题变量和组件库主题入口；不因局部修改迁移预处理器。
- 提取组件时将专属样式一起迁移，页面只保留排列、间距等外层布局；样式分文件时仍保持原有作用域，不因抽取产生全局选择器。
- 样式作用域遵循项目约定，覆盖第三方组件时限制选择器范围，避免全局污染。
- 外部内容默认按文本渲染；确需 `v-html` 或富文本时，先确认内容的可信边界，用户可控 HTML 须经过项目已有净化方案。方案缺失时明确缺口，不直接注入 DOM。

## 交付检查

- 检查调用方的类型定义、默认值、事件名称与更新时机。
- 覆盖空值、超长内容、禁用、加载与错误。
- 涉及表单或交互控件时，检查标签关联、可访问名称和键盘操作，保留组件库已有语义与焦点管理。
- 弹窗或浮层必须验证 Esc 关闭、焦点捕获与关闭后的焦点返回。
