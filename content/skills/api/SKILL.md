# API

先定位项目唯一请求入口、同领域接口和至少一个调用方。路径、方法、字段、响应层级、错误码和权限必须来自当前项目契约或源码。涉及页面编排或共享状态时，同时读取对应技能。

## 边界

- 只在项目既有 API 模块声明请求；页面、组件和 Hook 不直接创建 HTTP 客户端。
- 复用既有拦截器、鉴权、超时、取消、解包和错误处理；不复制其他项目的请求封装。
- API 模块不保存页面 loading、弹窗、分页或通知；这些留在调用方。

## 契约

- URL、查询、请求体、字段名和枚举保持后端原样，不为前端风格擅自改名或加映射层。
- 在 API 边界声明请求与响应类型；调用方按本项目实际响应层级取值（如 `data` 或 `data.data`）。
- 无法确认端点、字段、权限或响应层级时保留待确认项，不编造默认值、环境变量或 mock 契约。

## 调用

- 取消、重试和并发以后到响应或项目已有序号/取消机制为准，避免过期结果覆盖新结果。
- 列表包在 `{ list, total }` 内时，不要把整段响应或 Axios 外壳当成列表。

## 交付检查

- 核对 API 模块、请求入口和至少一个调用方的字段与取值路径。
- 覆盖成功、空数据、业务失败、网络失败和并发覆盖。
