# API

先定位项目唯一请求入口、同领域接口和至少一个调用方。路径、方法、字段、响应层级、错误码和权限必须来自当前项目契约或源码。涉及页面编排或共享状态时，同时读取对应技能。

## 边界

- 只在项目既有 API 模块声明请求；页面、组件和 Hook 不直接创建 HTTP 客户端。
- 复用既有拦截器、鉴权、超时、取消、解包和错误处理；不复制其他项目的请求封装。
- API 模块不保存页面 loading、弹窗、分页或通知；这些留在调用方。

## 契约

- URL、查询、请求体、字段名和枚举保持后端原样，不为前端风格擅自改名或加映射层。
- 涉及业务枚举或固定字典标识时读取常量技能，核对公共与所属业务定义并导入；API 类型可引用派生类型，不重新维护另一份码值或联合类型。
- 在 API 边界声明请求与响应类型；调用方按本项目实际响应层级取值（如 `data` 或 `data.data`）。
- 先确认拦截器如何判定业务成功与解包，再消费载荷；不要用 `res?.list ?? res?.data ?? []` 猜测响应结构或把失败伪装成空列表。
- 无法确认端点、字段、权限或响应层级时保留待确认项，不编造默认值、环境变量或 mock 契约。

## 调用

- 同一查询连续触发请求时，调用方复用已有取消或序号机制，仅允许最新有效请求更新结果、错误与 loading；较早请求晚返回也不能覆盖当前状态。
- 写操作的重试、幂等键和取消语义按项目契约处理；不能把取消请求当作服务端已撤销操作。
- 列表包在 `{ list, total }` 内时，不要把整段响应或 Axios 外壳当成列表。

## 文件传输（涉及时）

- 上传参数、文件限制和取消能力先查现有接口与上传组件；客户端校验由交互层承担，不能替代服务端校验。
- 下载前按项目契约确认响应是预期文件；接口可能返回错误 JSON/HTML 时，结合响应类型与错误结构识别，不能只凭 HTTP 200 或 Blob 类型直接保存。

## 交付检查

- 核对 API 模块、请求入口和至少一个调用方的字段与取值路径。
- 覆盖成功、空数据、业务失败和网络失败；涉及连续查询时，验证旧请求晚成功、晚失败或结束均不覆盖当前状态。
- 涉及下载时，验证正常文件和伪装成文件流的错误响应；合法 JSON/HTML 文件按下载契约区分。
