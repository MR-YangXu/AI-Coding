# Hook

先看现有 composable 与调用方。Hook 是可复用状态、副作用或独立复杂流程，不是页面脚本的搬运容器。涉及请求或共享状态时，同时读取对应技能。

## 优先复用已有能力

- 新建列表或表单时先检索公共分页、查询重置、选项加载、提交后刷新和上传流程；阅读 Hook 与至少一个调用方，确认输入、响应层级、状态归属、错误反馈及并发行为。
- 已有能力满足需求时，通过参数、回调和返回值接入，页面保留业务条件、接口适配和事件编排。已有 Hook 的复用不受“新增抽象需多个调用方”的限制，也不应在页面重复手写它已覆盖的流程。
- `usePageList`、`useSelectOptions`、`useAsyncListAction` 等名称只是候选能力示例，必须核实当前仓库实际存在和契约匹配；不能从另一项目直接复制导入、响应假设或缓存键。
- 能力只差可复用的通用扩展点时，评估最小向后兼容扩展并检查已有调用方；不存在或明显不匹配时，按下列条件决定就近实现或新建 Hook。

## 是否抽取

- 仅在满足至少一项时抽取为 `useXxx`：≥2 个调用方；输入输出明确、可独立理解的复杂流程；统一管理监听器、定时器、请求竞态或卸载清理。
- 页面专属的查询规则、提交决策、弹窗开关和当前行留在页面；通用执行机制可交给已有 Hook。不要把整页配置、业务请求、弹窗和状态打包进一个只为缩短文件的 `usePage`。

## 接口

- 导出最小的状态与方法，并为参数、返回值和回调提供明确类型。
- 不在 Hook 内隐藏页面级路由、整页表单或弹窗；依赖通过参数、回调或受控引用显式传入。
- 缓存键、存储格式、API 结构和提示文案以当前项目为准，不从其他仓库推断。
- 初始查询与重置快照独立保存；每次调用创建自己的可变状态，防止导入的配置被修改后影响其他页面实例或下次进入。

## 副作用

- 一个异步流程一个 loading，并由该流程的有效执行负责恢复；涉及请求竞态时遵循 API 技能，旧执行结束不能提前关闭当前执行的 loading。
- 监听器、定时器、观察器、Object URL 与未决请求必须有对应清理；只在组件 `setup` 同步调用，以保证生命周期有效。
- 不要仅为缩短页面文件而抽取。

## 交付检查

- 覆盖首次挂载、重复执行、失败返回、卸载与重新进入。
- 确认重复调用和离开页面后不会泄漏监听或未决请求。
- 确认新增页面确实复用了所述能力，响应层级与当前调用方一致；重置与重新进入不能继承上一次被污染的初始配置。
