# 页面

先读相邻页面、布局、权限、表单和反馈模式，再写 UI。页面是业务编排层；涉及 API、路由、组件或国际化时，同时读取对应技能。

## 边界

- 页面承载查询、排序、分页、筛选、表单提交、弹窗开关、当前行和局部 loading。
- 不要为缩短文件把整页状态抽成 Hook，或提升到全局 Store。
- 请求与原始响应类型留在 API 层；展示派生或纯转换沿用已有边界，没有既有边界时就近放在消费方，实际复用时才共享，不能改变传输契约。跨路由共享放 Store，页面私有 UI 放同域组件。

## 编排

- 请求成功前不假设返回形状；按本项目响应层级更新列表、总数和详情。
- 新建列表先看项目已有搜索和表格；小修复不要强行换基建。
- 模板避免复杂转换和多语句事件；用户可见文案走项目国际化入口。

## 异步与交互

- 每项异步闭合 loading，并处理空数据、失败、重复提交和过期响应。
- 详情弹窗和抽屉只接收所需最小数据，通过事件或约定方法与页面交互。
- 返回页面时的筛选、分页和滚动遵循项目既有模式，不要默默丢掉查询条件。

## 文件上传（涉及时）

- 先复用已有上传组件，按项目契约在请求前检查大小、数量及允许的文件类型，失败时明确反馈；未知限制先确认，不自行编造阈值。
- 大文件或长传沿用项目取消能力，离开页面时处理取消与清理；资源释放遵循 Hook 技能，取消不能被当作上传成功。

## 交付检查

- 覆盖加载、空结果、失败、重复请求以及返回该页时的行为。
- 确认复用的页面、组件、API 和路由证据；未确认的接口或权限不得写成已实现。
- 涉及上传时，验证有效文件、超限或不支持的类型、失败与取消后的状态恢复。
