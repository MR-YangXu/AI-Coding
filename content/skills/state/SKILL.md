# 共享状态

先读项目 Store 入口、最接近的模块和关键调用方。默认让状态靠近消费者；仅在确认需要跨路由或跨模块共享后再放入 Store。涉及动态路由或权限时，同时读取路由技能。

## 边界

- 沿用项目既有 Store 风格、目录和 `useXxxStore` 命名，不引入另一套状态方案。
- 页面查询、分页、排序、弹窗、表单草稿和局部 loading 留在页面或独立 Hook。
- 不要把页面实例、DOM、组件引用或短期 UI 状态放进全局 Store。

## 设计

- 一个 Store 围绕一个共享领域：源状态、派生值与 action 的职责可独立说明。避免两处维护同一事实。
- 复杂共享流程经 action 更新；深层组件不要随意改写其他模块状态。
- 登录、登出、权限、标签页和持久化改动必须检查相互联动。

## 异步与持久化

- action 明确成功值、失败处理、loading 所属和 reset 语义；登出或切站点后旧请求结果必须失效。
- 只有确实需要跨会话恢复的数据才加入既有持久化；Token 和敏感信息遵循当前安全边界，不写入日志或无关存储。

## 交付检查

- 覆盖登录切换、刷新、过期、重置和并发请求。
- 确认默认状态可回到可预测的初始值；跨路由读写与重置一致。
