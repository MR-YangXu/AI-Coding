# AI 编码基本规则

- 以需求的目标、范围和验收标准为准；关键业务事实或实体是否存在不明确时澄清，不编造业务事实，也不编造仓库中不存在的模块、API 或依赖。
- 先看 `package.json`、相关源码、相邻实现和项目已有约定，再决定修改位置。
- 如果项目有 `.ai-code/profile.md`，先读当前场景的推荐能力、源码入口、参考实现及可借鉴部分，以及禁止效仿项，再核实源码。该文件由项目维护，不代替组件契约；外部范例的导入和字段须在当前项目重新确认。
- 按任务选择相关技能，只执行涉及本次改动的交付检查；仅要求审查时，报告有证据的问题、代码位置、触发条件与影响，不自动修改代码。
- 通用技能适用于所有 Vue 项目；已启用的场景技能仅补充当前功能所需的要求。混合项目按功能归属和运行环境选择，可组合适用场景；场景被安装不代表对整个项目生效。
- 优先复用现有组件、请求层、工具和依赖；无既有先例不新增依赖；新增共享或平行抽象须有实际复用理由。
- 仅修改任务范围内的代码，不顺手重构、升级依赖或改动无关配置。
- API 字段、响应、枚举和权限以已确认契约或当前项目源码为依据；不跨项目照搬。资料与实现冲突时核对差异，影响当前任务且无法确认的关键项须澄清，不按“更严”自动选边。
- 禁止空 catch 吞异常、删除有效逻辑，或用 TODO、假数据冒充完成；保留 TypeScript 类型边界，不得用 `any`、忽略指令或关闭检查掩盖问题。
- 对异步交互处理加载、空结果、失败和资源释放；验证可观察的业务行为。
- 完成后运行适用的项目质量命令，区分本次问题和历史问题；分别报告类型检查、代码规则检查与构建结果，不能互相替代。检查缺失、失败和未运行不得写成通过。
- 不提交密钥、真实用户数据或含秘密的环境文件；前端可读取的环境变量不能用于保密。日志和上报不得输出令牌、完整 Cookie 或未脱敏个人信息。
- 涉及不可逆操作时先确认范围。

## 实现流程

项目准备与日常开发分别处理：首次接入、维护项目约定或公共能力变更时，按已核实源码维护 profile 的适用范围、推荐用途、源码入口和参考实现。文件不存在时先依据当前项目继续工作并说明缺口，不为每个任务新建档案；`init`、`sync` 不自动创建或覆盖 profile。

新建页面或涉及职责拆分的改动按以下流程推进；局部修复只执行相关步骤，审查任务只报告问题。

1. 明确交付范围：按用户要求区分原型、接口联调或完整功能；关键契约缺失时标明待确认项，继续完成不依赖它的工作，不能自行降级成假数据演示后宣称完成。
2. 检索并决定复用：读取相关能力的源码和已有调用方，参考相同用途与运行环境的实现，选择直接复用、兼容扩展或私有实现。不复用时说明具体需求、候选源码位置、能力缺口及不能合理扩展的原因；仅凭“更简单”或“更贴近设计稿”不能证明不匹配。
3. 确定职责与预期：按实际复杂度和项目约定确定状态、逻辑与展示归属，并明确本次交互的触发、状态变化和异常结果。具体页面组织由适用场景补充，不要求统一文件树。常规决策自主推进，无需逐步审批或另建流程文档。
4. 完成实现与验收：运行适用检查并验证已明确的行为；失败后修正并复查受影响范围。交付复用依据、实际命令结果、交互操作与观察结果三类证据，注明自动测试、浏览器或模拟验证，以及未运行、不适用和待联调项。模拟行为不能证明真实接口保存成功。

## 类型检查接入（涉及检查缺失或失效时）

- 先复现并区分检查配置、历史类型错误和新增错误；检查应用源码、构建脚本、全局声明及生成类型的边界。不能排除应检查的业务文件或降低类型约束来制造通过。历史问题不阻止无依赖的工作推进，但交付须保留失败状态。
- 在任务涉及项目检查建设或修复时，维护独立的类型检查脚本，参数以当前项目配置为准，并显式更新 `.ai-code/config.json` 的 `scripts.typecheck` 映射；当前 `sync` 保留已有映射，不会重新发现新增命令。先运行脚本，再核对 `ai:check` 实际执行结果；观察模式允许缺失项不阻断，不等于该项通过。
