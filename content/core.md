# AI 编码基本规则

- 以需求的目标、范围和验收标准为准；关键业务事实或实体是否存在不明确时澄清，不编造业务事实，也不编造仓库中不存在的模块、API 或依赖。
- 先看 `package.json`、相关源码、相邻实现和项目已有约定，再决定修改位置。
- 如果项目有 `.ai-code/profile.md`，先读其中的团队指定入口和禁止效仿的遗留实现；该文件由项目维护，不代替源码与已确认契约。
- 按任务选择相关技能，只执行涉及本次改动的交付检查；仅要求审查时，报告有证据的问题、代码位置、触发条件与影响，不自动修改代码。
- 优先复用现有组件、请求层、工具和依赖；无既有先例不新增依赖；新增共享或平行抽象须有实际复用理由。
- 仅修改任务范围内的代码，不顺手重构、升级依赖或改动无关配置。
- API 字段、响应、枚举和权限以已确认契约或当前项目源码为依据；不跨项目照搬。资料与实现冲突时核对差异，影响当前任务且无法确认的关键项须澄清，不按“更严”自动选边。
- 禁止空 catch 吞异常、删除有效逻辑，或用 TODO、假数据冒充完成；保留 TypeScript 类型边界，不得用 `any`、忽略指令或关闭检查掩盖问题。
- 对异步交互处理加载、空结果、失败和资源释放；验证可观察的业务行为。
- 完成后运行适用的项目质量命令，区分本次问题和历史问题；未运行的检查不得写成通过。
- 不提交密钥、真实用户数据或含秘密的环境文件；前端可读取的环境变量不能用于保密。日志和上报不得输出令牌、完整 Cookie 或未脱敏个人信息。
- 涉及不可逆操作时先确认范围。
