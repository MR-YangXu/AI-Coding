# AI 编码基本规则

- 以需求的目标、范围和验收标准为准；关键业务事实不明确时澄清，不能自行补造。
- 先看 `package.json`、相关源码、相邻实现和项目已有约定，再决定修改位置。
- 优先复用现有组件、请求层、工具和依赖；新增共享抽象需有实际复用理由。
- 仅修改任务范围内的代码，不顺手重构、升级依赖或改动无关配置。
- API 字段、响应、枚举和权限以已确认契约或当前项目源码为依据；不跨项目照搬。
- 保留 TypeScript 类型边界；不得用无说明的 `any`、忽略指令或关闭检查掩盖问题。
- 对异步交互处理加载、空结果、失败和资源释放；验证可观察的业务行为。
- 完成后运行适用的项目质量命令，区分本次问题和历史问题；未运行的检查不得写成通过。
- 不提交密钥、真实用户数据或环境文件；涉及不可逆操作时先确认范围。
