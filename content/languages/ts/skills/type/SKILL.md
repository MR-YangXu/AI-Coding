# 类型定义

本技能适用于通用前端、后台和 H5。全局指项目公共模块中的共享类型，局部指所属业务、页面或组件的类型；全局共享仍通过模块导入，不等于无须导入的全局声明。

## 查找范围与停止条件

1. 按已读取的项目约定或现有导入，先查公共类型导出、当前业务入口与生成类型来源。路径沿用项目结构；转导出需追踪实际定义，不为凑齐目录创建文件。
2. 入口不明或没有匹配定义时，按业务名称、类型名、关键字段定向搜索全项目。先返回候选路径和命中片段，再读取相关声明；不能因为当前业务目录没找到就直接复制或新建。
3. 核对候选的业务语义、契约与归属；修改共享契约时检查受影响的直接调用方。信息不足或出现冲突时继续补读，证据足以决定复用或新增后停止，不为每个局部类型逐文件证明全库绝无重复。
4. 会话中已核实且仍有效的定义与调用证据直接复用，API、常量技能已确认的来源不重新检索；代码、契约或任务范围变化时只补查受影响部分。

## 全局与局部归属

- **全局公共类型**：跨业务共享且语义、契约一致的稳定定义，放在项目既有公共模块并通过其公共入口导出。业务实体不因被多个页面引用就自动变成全局类型；确需提升时先确定公共领域，再迁移调用方。
- **业务局部类型**：请求参数、原始响应和领域实体由所属 API 或领域模块维护，通过该模块已有入口引用。已有生成类型作为契约来源，不手改生成文件，不把业务类型全部汇总进公共入口。
- **页面或组件局部类型**：页面查询、表单和展示类型就近定义；Props、事件载荷和逻辑函数的输入输出由所属模块维护。需要独立维护或多文件共用时再抽到同域 `types.ts`，不为每个页面固定生成类型文件。
- 类型专用导入沿用项目写法，支持时使用 `import type`。公共模块不反向依赖业务，API 模块不反向依赖页面；不把业务实体集中到全局 `.d.ts` 声明文件。

## 禁止多处定义（强制）

- **同一业务语义、同一契约只能有一份权威类型定义。** 页面、组件、逻辑函数、API 和 Store 从所属模块导入；不得在全局与局部各维护一份，换名复制字段结构同样违规。
- 允许转导出、导入别名，以及从权威定义派生的 `Pick`、`Omit`、索引访问类型或具有明确语义的扩展；这些引用或派生不算重复定义。不要为了转发一次类型新增文件或空接口。
- 页面选择态、格式化文本等展示字段通过派生或组合表达，不复制原始接口字段后独立维护，也不回写 API 契约。业务码值类型从权威常量派生，不再手写另一份联合值。
- 字段结构相同不代表业务语义相同，不强行合并不同契约，也不限制正常的局部类型推断。发现历史重复时核对来源与调用方，在任务范围内迁移到唯一来源；不因同名或同结构自动删除、合并或全库重构。

## 定义与推断

- `type`（类型别名）和 `interface`（接口）沿用项目已有约定；没有约定时，对象契约可用 `interface`，联合、元组和映射类型用 `type`。不为统一关键字改写无关代码，不强制添加 `I` 或 `T` 前缀。
- API、组件和导出函数的输入输出应有明确契约；能从已有定义可靠推断时不重复声明结构。局部变量、回调参数和简单返回值优先推断；空数组、初始空值或可能过度收窄的状态按实际值域补类型。
- 业务码值从已有常量派生类型，例如 `typeof STATUS[keyof typeof STATUS]`，不手写另一份联合值。实体状态与包含“全部”的筛选值分开建模，提交请求时按契约转换，不能把筛选值扩进实体状态。
- 保留 ID、码值、日期等传输字段的原始类型，以及缺省、`undefined`、`null` 的实际区别。不要用 `string | number`、全字段可选或 `Partial` 掩盖不清楚的契约；只有接口确实支持局部更新时才按需派生可选字段。
- 已知字段使用明确结构；只有键确实动态时才用 `Record`（键值映射）。泛型应表达输入输出关系，不为单次实现引入无用途的类型参数。

## 外部值与收窄

- 未验证的外部值先按 `unknown`（未知类型）处理，在边界复用已有解析或校验能力并收窄；TypeScript 声明和请求泛型不等于运行时校验，不为本次页面另建一套校验框架。
- 不用 `any`、`as unknown as`、非空断言或忽略错误掩盖不匹配。确需断言时，应有编译器无法表达的约束依据；`as const` 的字面量保留用途不属于绕过检查。
- TypeScript 4.9+ 中，静态配置或模拟数据需要校验结构并保留推断时可使用 `satisfies`（满足类型约束）；不为使用该语法升级项目依赖。模拟数据复用真实契约，不凭演示字段反推接口。

## 验证

核对本次改动的定义归属、导入与派生关系，以及共享契约的受影响调用方。类型检查由基础规则统一安排：本次代码错误修复后复验，未处理原因的历史或环境故障不原样重跑；完整日志落盘，先看摘要，必要时补读相关片段。项目已有类型检查验证类型兼容性，不能自动阻止同义重复声明；本包尚未提供类型重复定义检查器。缺失、失败或未运行分别如实报告。
