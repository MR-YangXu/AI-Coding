# 配置、日志与部署

适用：环境配置、日志、Docker、Compose、PM2、Nginx、灰度发布和监控。课程主题：第 36—44、62、76—80、95、107 章及实战部署。

## 配置与日志

列出启动必需配置、类型、默认值和来源优先级；启动时验证缺失、非法数字与布尔字符串。ConfigModule/ConfigService 根据项目约定管理配置，密钥经部署环境或秘密管理服务注入。不要把课程复制 `.env` 到 `dist` 的方式无条件用于生产镜像、仓库或前端产物。

Nest Logger 足够时直接使用；需结构化输出、统一传输和保留策略时集成现有日志系统或 nest-winston。区分开发可读日志与生产结构化日志，记录时间、级别、请求关联标识、操作和结果。Winston transport（输出通道）失败不能拖垮业务请求。

请求日志使用允许字段，脱敏 Authorization、Cookie、密码、验证码及敏感业务数据。上传、流式响应和大请求体避免全量记录。客户端 IP 仅在可信代理边界内解释转发头，不无条件信任 `X-Forwarded-For`。IP 地理查询不放进每个请求的关键路径，也不把它当成精确位置。

## 构建与容器

按依赖锁文件构建，多阶段镜像只携带运行产物及必要依赖；`.dockerignore` 排除秘密、开发缓存和无关文件。基础镜像匹配 Node、CPU 架构及原生依赖。Alpine 体积较小但 musl（C 标准库实现）与二进制兼容性需验证，不能一律规定使用。

构建阶段 ARG 与运行时 ENV 作用不同；二者都不是传递构建秘密的安全机制。CMD/ENTRYPOINT 根据启动和参数覆盖需要选择，ENTRYPOINT 可通过运行配置覆盖，不把它当成不可变安全边界。

镜像层和容器可写层不是持久化备份。数据库和上传文件使用明确命名的数据卷或外部存储，配置备份及恢复演练；声明 VOLUME 不能保证在删除数据卷后仍保留数据。

容器使用适当的非 root 用户、权限、资源限制和信号转发。确认启动的主进程不会被 shell 隐藏而失去优雅关闭；校验所选 exec 形式和 init 方案。

## 多服务运行

Compose 通过服务名与内部网络连接应用、数据库和 Redis；默认不把不必要的数据库端口开放到外部。`depends_on` 的启动顺序不等于服务已就绪，配置健康检查及应用连接重试，并验证冷启动。

容器重启策略、PM2 和编排平台各有职责。已有容器/平台提供进程恢复时，不必默认再套 PM2；需要多进程或明确 PM2 能力时再使用并验证 `pm2-runtime`、日志及终止行为。多进程/多实例不能使用进程内 Session 或本地缓存假装共享状态。

## 网关与发布

Nginx 静态托管明确 SPA（单页应用）路由回退；反向代理检查尾斜杠、路径重写、Host、可信转发头、请求体限制和超时。WebSocket 升级与 SSE 流需要各自配置并实际验证。

`location` 匹配规则应以真实配置测试，尤其是前缀、正则、嵌套和 `^~` 的组合；不要用简化优先级表代替测试。负载均衡算法及第三方模块按安装版本核对，`fair` 并非标准安装必然内置。

灰度发布先定义稳定分组、流量比例、观测指标和回滚条件，再路由至不同版本。客户端 Cookie 分组不是权限凭据；数据库变化需新旧版本兼容。前后端版本和静态资源缓存策略共同验证。

## 验收证据

验证冷启动、数据库就绪、迁移顺序、健康/就绪探针、进程终止、连接释放、容器重启和数据持久化。日志可按请求关联定位失败且不包含秘密；CPU/内存/磁盘监控区分宿主机与容器额度，监控入口本身应受保护。

部署命令、迁移和对外暴露属于实际环境变更，遵循当前任务授权及项目发布流程；本技能不自动授予生产发布权限。没有在目标环境运行，不声明部署通过。
