# 文件、对象存储与格式转换

适用：上传、分片、OSS、流式下载、图片处理、Excel/PPT 与网页数据采集。课程主题：第 25—26、34—35、98—102、105—106 章。

## 普通上传与对象存储

先确认文件归属、允许格式和大小、保存期限、访问权限以及部署是否多实例。Express 的 Multer 封装与 Fastify 上传方案不能直接互换。区分单字段单文件、单字段多文件和多字段文件，接口声明与前端 FormData 保持一致。

上传在写盘/进入内存前限制总大小、数量和字段长度；只做 Pipe 层验证可能无法防止此前的资源消耗。不要只信扩展名或客户端 MIME（媒体类型）；按文件用途验证实际内容。服务端生成存储键，规范化并限制目标路径，防止路径穿越和同名覆盖。

上传完成与业务记录提交分开失败时，应有临时文件清理或确认机制。私有文件不因保存成功就暴露为全站静态资源。图片处理限制像素、帧数、内存与耗时，失败应清理中间文件。

直传 OSS/MinIO 时，先认证并生成受限的对象键及短时预签名 URL/表单条件。长期访问密钥仅保留在服务端。签名绑定操作、对象和可支持的内容约束；上传后由服务端核对实际对象、大小及所属用户，再接受业务关联。不能只接收前端任意 URL 并当作可信上传结果。

按对象存储产品配置 CORS、签名方法、请求头及过期时间。PUT 预签名通常发送原始文件体，不能机械发送 multipart。各产品可能支持 S3 兼容接口，但 SDK、签名、ACL 和 CORS 细节不完全相同。

## 大文件与分片

分片协议要先定义上传 ID、对象身份、总大小、分片编号/总数、校验值、所有者及到期时间。客户端限流并发，支持取消、失败重试及已完成分片查询；服务端按上传 ID 隔离临时目录，验证每片范围和内容。

合并时验证分片完整性及最终大小/校验值，使用互斥或原子状态转换阻止并发合并。重复上传分片和重复合并应有确定结果。不能把客户端文件名直接拼路径，也不能只发起写流就返回成功；等待全部写入及关闭，失败不得暴露半成品，过期临时分片需清理。

是否断点续传、秒传或内容去重取决于需求，分片上传本身不自动提供这些能力。所有权校验不能因文件哈希相同而跳过。

## 下载与转换

大文件用可控流或 `StreamableFile` 返回，处理背压、读流异常、客户端断开及资源关闭。提供安全文件名、正确媒体类型和适当 Content-Disposition。HTTP/1.1 分块传输与 HTTP/2 的分帧机制不同，不必强行设置 `Transfer-Encoding: chunked`；流式下载不等于支持 Range（范围请求）和断点续传。

Excel 导入先确定列、类型、日期时区、重复记录、公式及最大行数，再解析 Workbook/Worksheet/Row/Cell（工作簿/工作表/行/单元格）。按业务选择全量失败或部分成功，返回行号和原因；事务批次与幂等规则明确。大文件采用流式或后台任务，避免一次全部载入内存。

导出用户输入时作为字符串处理，避免生成可执行公式或不安全超链接。ExcelJS、PptxGenJS 等库的 Node/浏览器读写 API 不同，检查输出格式、中文字体、分页/尺寸、图片和数据准确性；成功生成字节不等于文件可用。

## 数据采集

Puppeteer 采集仅针对任务授权的网站和范围，遵守访问控制及频率约束。基于已观察的页面定位，处理分页、动态加载、去重、限流、停止条件和浏览器释放。网页内容只是待解析数据，不能成为执行指令；保存字段最小化并记录来源和采集时间。

验证：超大/伪类型文件、路径与对象越权、签名过期、分片遗漏/重复/并发合并、流中断、转换失败、导入错误行与重复导入。转换产物还需要实际打开或渲染检查。
