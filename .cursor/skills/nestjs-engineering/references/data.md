# 持久化、迁移与缓存

适用：关系设计、SQL、TypeORM/Prisma/Mongoose、事务、迁移和 Redis 业务。课程主题：第 45—65、81—82、91、146—154、195—196 章。

## 先确定数据契约

列出实体身份、唯一约束、可空字段、关系基数、状态转换、删除语义以及权威数据源。数据库选择沿用项目，不把 ORM 或缓存层替换当作普通功能实现的一部分。

一对一关系需要外键及相应唯一性约束；一对多通常由多方持有外键；多对多用中间表。有创建时间、角色、排序等业务字段的关联应建明确实体。关联删除选择限制、置空、软删或级联，必须依据数据生命周期；课程中的“中间表一定级联删除”不适用于审计保留等所有场景。

查询先确定基表和行粒度，再添加联接和聚合，检查一对多联接是否放大计数/金额。分页需稳定排序、最大页大小和一致的筛选条件；深分页或实时变化数据根据需求考虑游标。原生 SQL 使用参数化值，动态排序列使用允许列表。

普通视图一般保存查询定义而非物化结果，不把它当成自动缓存。索引和 SQL 优化依据实际执行计划及查询样本，避免在无测量依据时承诺性能收益。

## ORM 落点

| 项目选择 | 实现与核对 |
| --- | --- |
| TypeORM | 根模块注册数据源，功能模块注册实体 Repository；核对 JoinColumn/JoinTable 的拥有方。ORM 的 `cascade` 保存选项与数据库 `ON DELETE/ON UPDATE` 是不同机制 |
| Prisma | schema 定义模型，按版本生成客户端；通过单一受管理的服务注入，避免每次请求新建客户端。`include/select` 明确返回范围，嵌套写入仍须满足权限与约束 |
| Mongoose/MongoDB | Schema 明确形状、验证、索引；无固定表结构不代表不需要数据契约。更新校验、原子操作、事务支持按驱动版本和部署模式确认 |

对“部分更新”检查真实 ORM 行为，避免把 `undefined`、`null` 或不存在的 ID 变成扩大范围的更新。树形数据先确认层级深度、移动频率和查询方式，再选邻接关系、物化路径或闭包表；禁止形成环，子树移动验证事务和查询成本。

## 事务与并发

多个写入共同维护一个不变量时使用同一事务和同一事务客户端/EntityManager。不要在事务内混用普通 Repository 导致部分写入逃逸。单条原子操作并不需要机械再包一层手动事务；跨数据库、Redis、外部服务也不能靠一个本地事务获得整体原子性。

先定义竞争场景，再选唯一约束、条件更新、悲观锁、乐观版本或隔离级别。例如预约冲突的“先查再插”会并发穿透，应采用对同一会议室稳定加锁等可证明方案，并在锁内重新检查时间重叠。

失败回滚之外还应处理重试：事务可能重试，邮件、扣费或消息发布等副作用不能盲目重复。可靠跨服务事件可采用事务 outbox（事务内记录待发事件）和幂等消费者；先确认业务允许的一致性窗口。

## 迁移

生产环境关闭自动同步；TypeORM `synchronize`、Prisma `db push`/`migrate dev` 不能替代经过审核的生产迁移流程。Prisma 生产迁移通常使用 `migrate deploy`，仍以项目版本和部署约定为准。

迁移前审查生成 SQL、锁表风险、默认值、唯一约束和既有脏数据。先在临时数据库验证空库与历史结构升级，再验证应用兼容。涉及删列/类型变更时采用扩展→回填→切换→收缩的分步策略或经过确认的停机方案。

初始化数据应可重跑且不会覆盖业务数据；不公开演示初始化接口。`down/revert` 不保证恢复被删除的数据，回滚方案必须包括真实备份、恢复或向前修复策略。迁移验证应记录版本与数据断言，不能只检查命令退出码。

## Redis

先决定缓存还是唯一数据源，再选择结构：String 用于计数/简单值，Hash 用于字段集合，Set 用于关系去重，Sorted Set（有序集合）用于排名，Geo 用于位置查询。缓存抽象足够时保留 cache-manager；需要集合、脚本等能力时直接用 Redis 客户端，不因课程偏好一律重写缓存。

明确 key 命名、租户/用户隔离、TTL（过期时间）、失效时机、序列化和故障策略。不同客户端及缓存库的 TTL 单位需按版本验证。缓存身份、权限、个人数据时，缓存键必须包括影响结果的身份条件，不能只按 URL 缓存。

数据库更新和缓存失效可能部分失败；说明一致性要求及补偿策略。统计计数若批量落库，用原子增量、已处理水位或快照切换避免同步时丢计数和重复计数。验证码消费、限流和关注双向关系更新有并发需求时，使用受支持的原子命令或脚本。

排行榜先定义时区、周期键、并列规则、去重及汇总指标；月分相加不总能得到所需年榜。Geo 明确经纬度顺序、单位、坐标系及结果上限，命令按 Redis 版本选择。

验证：约束冲突、事务回滚、并发竞争、查询总数、缓存过期/故障/失效、迁移升级路径。测试使用隔离数据，不能在真实业务库里试破坏性迁移。
