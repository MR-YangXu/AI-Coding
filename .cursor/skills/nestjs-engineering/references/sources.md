## 实际覆盖

通过内置浏览器，在用户自行完成登录后，从目录提取到 200 个不同章节链接，并逐个访问页面。每页定位正文区域，核对正文是否非空，提取正文标题层级与章末段落用于整理。200/200 个章节均有正文；没有用目录标题填补访问失败章节。

阅读方式是正文结构与章末小结核对，并非逐段精读 200 章的全部代码、图片和评论。页面正文字符计数只用于确认加载，不作为内容质量或阅读深度指标。原文、代码和图片未打包保存；章节文件是简短原创摘要，不替代小册。

八份主题参考是围绕课程主题独立编写的工程规则，包含额外的正确性、并发、资源和授权约束。它们不全部来自课程，也不代表原作者的逐字结论。采用具体 API 前，仍需核对当前项目依赖及对应版本文档。

## 安装与调用

技能目录名与 frontmatter（文件头部元数据）的 `name` 同为 `nestjs-engineering`。当前位于项目的 `.cursor/skills/nestjs-engineering/`，Cursor 可发现其中的 `SKILL.md`。复制到其他项目时保留整个目录及 `references/` 的相对结构。

在 Cursor 的 Agent（智能体）聊天中输入 `/` 并搜索 `nestjs-engineering` 手动调用，也可由匹配任务自动选用。打开 Cursor 的技能列表确认发现状态；未在实际 Cursor 客户端验证之前，不将文件格式检查说成客户端验证通过。

示例请求：

- 使用 nestjs-engineering，为现有预订接口增加并发冲突保护，保持当前接口格式。
- 使用 nestjs-engineering，审查登录刷新和账号冻结后权限失效的行为，只报告问题。
- 使用 nestjs-engineering，实现当前项目的 MinIO 直传，沿用现有认证与文件归属模型。

本目录是独立技能交付物，没有加入 ai-code 的分发能力清单，也没有修改其同步和安装行为。
