# 接口、校验与表示层

适用：新增或修改 HTTP/GraphQL 接口、DTO、序列化、错误格式、文档和国际化。课程主题：第 5、11—14、19—24、83—88、108、197—199 章。

## 输入边界

先确定传输位置与类型：路径参数、查询参数、JSON、表单 URL 编码或 multipart（多部分表单）。路径及查询默认来自字符串；缺失值、空字符串、`null`、`false`、`0` 分别处理。浏览器发送 FormData 时由浏览器生成含 boundary（分隔符）的 Content-Type，避免手写不完整请求头。

DTO 使用具有运行时信息的类；TypeScript 接口或类型断言不能提供请求校验。核对 `ValidationPipe` 的转换、白名单及未知字段策略，并对实际输入测试。不要用宽泛隐式转换处理布尔值，例如字符串 `"false"` 被简单布尔转换后会成为真值。

数组、嵌套对象必须明确元素规则、实例转换及深度/数量约束。更新 DTO 要区分“未提供”和“明确清空”，不能因为使用 `PartialType` 就允许修改所有创建字段。依据 HTTP/Swagger/GraphQL 场景选择对应 mapped-types（类型映射）工具，验证元数据没有丢失。

规则落点：格式和范围放 Pipe/DTO；资源存在、所有权和业务状态放服务层；唯一性、外键与关键并发不变量放数据库。注册前先查询用户名不能替代数据库唯一约束。

## 响应、错误与序列化

沿用项目响应契约，不因课程使用 `{code,message,data}` 就统一改动所有接口。若确实建立包装层，处理分页、空响应、文件、重定向和流式输出的例外，并同步消费者与 OpenAPI。

`@Res()` 手动接管响应会改变 Nest 默认返回值处理；需要框架继续发送返回值时核对 `passthrough` 配置。避免手动 `send()` 后又让框架重复写入。

错误映射区分 400（无效输入）、401（未认证）、403（无权限）、404（不存在）和 409（约定的状态或唯一冲突）。按项目既有契约决定可暴露的信息，不泄露数据库语句、堆栈、密钥。过滤器应兼容校验错误数组、字符串消息及未知异常，保留可追踪的内部日志。

Entity（持久化实体）可以配合 ClassSerializerInterceptor 做输出过滤，但不因此要求所有接口直接暴露实体。涉及稳定外部契约、字段聚合或敏感对象时，使用明确的响应 DTO/映射函数通常更容易控制边界。

选择实体序列化时，验证返回值是装饰器适用的实例，或明确设置转换目标；普通对象、查询构建器原始结果、嵌套数组、分页包装不一定自动符合预期。`@ApiHideProperty` 只隐藏文档，不能从真实响应删除密码字段。显式允许输出字段比依赖遗漏排除更容易审查。

## 接口文档与版本

Swagger/OpenAPI 描述实际请求、响应、错误、分页及认证方案，并测试生成文档与真实响应一致。文档标记 Bearer 认证不会自动启用鉴权。生产文档入口按团队访问策略开放。

需要版本共存时先查客户端升级约束，再选择 URI、Header、媒体类型或自定义版本提取；明确默认版本、未知版本和中性版本的路由行为，并逐个验证。不要把教材中的版本语义直接当成当前版本事实。

国际化保留稳定的错误码，仅本地化面向用户的信息。确定语言来源优先级、允许语言及回退；检查参数插值和 DTO 错误也遵循同一策略。翻译资源进入构建产物，私密环境配置不随之公开。

## GraphQL

先确认项目使用 schema-first（先定义模式）还是 code-first（先定义代码），保持一种清晰的权威来源。客户端只能选择 schema 允许且有权访问的字段，不是任意读取数据库。

Query 用于读取，Mutation 用于变更；Resolver 调用业务服务。验证变量、可空性、列表及错误表现；敏感字段和对象级访问在解析层或服务层鉴权。限制查询深度、复杂度及分页规模，检查 N+1（逐条额外查询）问题；需要批量加载时按请求隔离缓存，避免跨用户泄露。

Apollo 等客户端变更后要明确更新或失效缓存。Schema、Prisma 模型与 React 组件类型不是同一契约；数据库字段变更不能直接传播成公开 API 变更。

验证至少覆盖：合法与非法参数、字符串布尔转换、未知字段、敏感字段是否真实排除、文档一致性，以及所修改接口的授权和错误路径。
