# 实战业务与前后端交付

适用：完整业务功能、与 Nest 接口联调的 React 页面、课程实战结构回查。主题对应图书第 27—33 章、会议室第 109—139 章、考试第 155—171 章、聊天室第 175—194 章。

## 业务契约优先

原型用于确认流程，不能决定权限和数据规则。先确认角色、资源所有者、输入输出、状态转换、并发情况、取消与恢复行为；沿现有模块做最小完整功能。不因教材采用 React/Ant Design、某种 ORM 或部署方案就迁移当前技术栈。

| 业务 | 必须明确的不变量 | 验证场景 |
| --- | --- | --- |
| 图书 CRUD（增删改查） | 图书身份、字段校验、图片归属、修改权限；文件数据库仅适合教学/受限原型 | 同名/无效输入、无权限修改、重复提交、删除后分页边界 |
| 会议室预订 | 时区、起止时间、占用状态、审批者、取消资格、重叠条件 | 同一会议室并发申请、批准与取消竞争、相邻时段、跨日/时区 |
| 考试与判卷 | 试卷版本、题目稳定 ID、题型与答案 schema、发布/回收状态、可答时间和次数 | 重复交卷、编辑后旧答卷、重算成绩、截止边界、非作者修改 |
| 聊天与好友 | 好友申请状态、房间成员、发送者可信身份、消息类型和可见范围 | 重复同意、并发私聊建房、退群后发消息、断线补拉、附件和收藏越权 |

预约常用半开区间 `[start,end)`；重叠条件为 `existing.start < end && existing.end > start`，是否允许端点相接须由业务确认。数据库事务/锁内验证冲突，不能只靠前端禁用时间或“先查后插”。

试卷内容在实现编辑器前定义可校验且可版本化的结构。题目 ID 不用数组下标，编辑更新保持不可变引用，草稿、预览、发布版本分别管理。向考生返回的数据排除正确答案和评分规则；由服务端按对应试卷版本评分，重试不能重复累计成绩或排名。

一对一聊天室用规范化的参与者组合及唯一约束防止并发建出多个房间。好友关系是否对称、拉黑/删除后能否发消息、群邀请权限需明确，不能根据课程演示自行扩展权限。

## 列表、表单与编辑状态

先核对分页、筛选字段、日期格式和错误契约。搜索条件变化时按产品规则重置页码；删除最后一条后的页码回退应可预测。旧成功、旧失败和旧 `finally`（结束回调）都不得覆盖新查询状态，通过取消或请求身份控制。

编辑弹窗以实体 ID 和打开会话确定回显来源。切换实体、关闭重开或后台刷新时明确是否保留未提交草稿；迟到详情响应不能覆盖当前实体。提交时锁定重复操作，失败保留输入并显示可执行错误；成功后按契约更新列表或失效缓存。

日期和时间先组合为明确时区的值再提交；前端组件值、ISO 字符串、时间戳及数据库类型之间的转换集中管理。统计视图声明时间范围、筛选条件及聚合粒度，空数据不能当成请求失败。

图表销毁实例并清理尺寸监听；文件预览释放 Object URL（对象地址）；WebSocket/SSE 监听和轮询按生命周期释放。React Effect（副作用）依赖要反映真实读取值，处理开发严格模式下重复建立/清理；`useMemo/useCallback` 仅在身份契约或测量收益支持时添加。

前端路由拦截改善用户体验，服务端仍是授权权威。token 刷新规则读取 [auth.md](auth.md)，不要在每个页面再写一套。上传规则读取 [files.md](files.md)，实时消息读取 [async.md](async.md)。

保留表单标签、弹窗可访问名称、键盘操作、错误提示及焦点返回；拖拽编辑器需要可替代的键盘/按钮操作，不能只支持拖拽。

## 一条完整验收链

按真实角色经前端或接口完成“创建→查询→修改→状态变更→失败恢复”，检查数据库与缓存结果。结合任务验证跨用户访问、重复操作、并发、刷新/重开、浏览器断线以及部署后静态资源路径。

涉及多个模块时先验证最小纵向流程，再扩大功能。课程中的手动点击成功不能替代当前项目的回归用例；服务间通信、生产部署、真实邮箱/OSS 等只在确实执行后记为通过。
