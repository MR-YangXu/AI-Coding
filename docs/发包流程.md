2. 注册用户名、邮箱、密码

按提示在浏览器完成登录。也可：

```bash

```

然后按提示输入用户名、密码、邮箱；若开启 2FA，再输入 OTP。

### 1.3 确认登录成功


### 1.4 建议开启 2FA

https://www.npmjs.com/settings/~/account → Two-Factor Authentication

## 2. Scope 与包名权限

本包使用 **scoped 包名** `@agent-xy/ai-code`。

### 2.1 两种合法归属方式

1. **用户 scope**：npm 用户名恰好是 `agent-xy`，则可直接发 `@agent-xy/*`
2. **组织 Org**：在 https://www.npmjs.com/org/create 创建组织 `agent-xy`，把发布账号加为成员（至少有 publish 权限）

若账号既不是 `agent-xy`，也不是 `@agent-xy` Org 成员，发布会失败（常见 `403` / `ENEEDAUTH` / `not authorized`）。处理方式：

- 加入或创建 `@agent-xy` Org，或
- 改 `package.json` 的 `name` 为你有权限的 scope（并同步改 README 里的安装命令）

### 2.2 检查包名与版本是否冲突

```bash
# 查看线上是否已有该包
npm view @agent-xy/ai-code

# 只看版本列表
npm view @agent-xy/ai-code versions --json
```

判定：

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| `404 Not Found` | 从未发布 | 可用 `0.1.0` 做首发 |
| 有包，但无当前 `version` | 可发该新版本 | 直接走发布前检查 |
| 版本列表已含当前 `version` | **不能覆盖** | 必须改 `package.json` 的 `version` 再发 |

本仓库当前线上已有 `0.1.0`，本地若仍是 `0.1.0` 且内容有变更，先升版本（见第 5 节）。

## 3. 本仓库 `package.json` 发布相关字段（核对清单）

发布前在根目录打开 `package.json`，确认与下表一致或按需调整：

```json
{
  "name": "@agent-xy/ai-code",
  "version": "0.1.1",
  "description": "Vue 2, Vue 3 and React AI coding rules and verifiable quality checks",
  "type": "module",
  "bin": {
    "ai-code": "bin/ai-code.mjs"
  },
  "files": [
    "bin",
    "src",
    "content",
    "README.md",
    "LICENSE"
  ],
  "engines": {
    "node": ">=18"
  },
  "license": "MIT",
  "repository": {
    "type": "git",
    "url": "git+https://github.com/MR-YangXu/AI-Coding.git"
  },
  "publishConfig": {
    "access": "public",
    "registry": "https://registry.npmjs.org/"
  }
}
```

要点：

| 字段 | 作用 |
| --- | --- |
| `name` | 线上包名；scoped 包必须带 `@scope/` |
| `version` | 每次发布必须**未占用**；遵循 semver |
| `bin` | CLI 入口；文件需有 shebang `#!/usr/bin/env node` |
| `files` | 白名单：只打进这些路径；`test/`、`docs/`、`fixtures/` 默认不进包 |
| `publishConfig.access` | scoped 包默认 private；`public` 才能免付费公开发布 |
| `LICENSE` + `license` | 开源协议一致 |

不要把 `.env`、密钥、本地 `*.tgz`、测试夹具误打进包。本仓库靠 `files` 白名单控制，一般够用；若要额外排除，可加 `.npmignore`。

## 4. 发布前本地验证（必做）

全部在仓库根目录执行。

### 4.1 跑测试

```bash
npm test
```

失败则先修，不要发。

### 4.2 预览将要上传的文件

```bash
npm pack --dry-run
```

期望 Tarball 大致包含：

- `package.json`、`README.md`、`LICENSE`
- `bin/ai-code.mjs`
- `src/**`（含 `adapters/`、`check.mjs`、`project.mjs`、`quality.mjs`、`scenarios.mjs`）
- `content/**`（common、frameworks、languages、scenarios、templates）

不应包含：`test/`、`docs/`、`fixtures/`、`.git/`、根目录历史 `*.tgz`（若误出现，检查 `files` / `.npmignore`）。

### 4.3 打真实 tarball 并模拟消费者安装

```bash
# 生成例如 agent-xy-ai-code-0.1.1.tgz
npm pack

# 临时目录模拟安装（路径按实际 tarball 名改）
TMPDIR=$(mktemp -d)
cd "$TMPDIR"
npm init -y
npm install /绝对路径/到/ai-code/agent-xy-ai-code-0.1.1.tgz

# 验证 CLI 可用
npx ai-code --help
```

本包是 CLI，不是给业务代码 `import` 的库；用 `--help` / `init --no-install` 验证即可。

验完后删掉根目录临时 tarball，避免误提交：

```bash
cd /path/to/ai-code
rm -f agent-xy-ai-code-*.tgz
```

## 5. 版本号怎么升

npm **禁止覆盖已发布版本**。本地改完代码后：

```bash
# 补丁：0.1.0 → 0.1.1（修 bug、小改文案/技能）
npm version patch --no-git-tag-version

# 次版本：0.1.0 → 0.2.0（新场景、新命令、兼容增强）
npm version minor --no-git-tag-version

# 主版本：0.1.0 → 1.0.0（破坏性变更）
npm version major --no-git-tag-version
```

`--no-git-tag-version` 只改 `package.json`，不自动 commit/tag。若希望 npm 顺带打 git tag：

```bash
npm version patch   # 会改 version + 创建 commit + tag（需干净工作区）
```

也可手改 `package.json` 的 `"version"`，效果相同。

**本仓库下次发布：** 线上已是 `0.1.0`，本地有改动 → 至少升到 `0.1.1`（或按变更幅度选 minor/major）。

## 6. 正式发布

确认：

1. `npm whoami` 正确  
2. `package.json` 的 `version` 线上不存在  
3. `npm test` 通过  
4. `npm pack --dry-run` 内容正确  
5. `publishConfig.access` 为 `public`

```bash
# 方式 A：依赖 package.json 里的 publishConfig（本仓库已配置）
npm publish

# 方式 B：显式指定（更稳妥，与配置重复无害）
npm publish --access public

# 开启 2FA 时
npm publish --access public --otp=你的一次性密码
```

成功时终端会打印类似：

```text
+ @agent-xy/ai-code@0.1.1
```

常见失败：

| 错误 | 原因 | 处理 |
| --- | --- | --- |
| `You cannot publish over the previously published versions` | 版本已存在 | 升 `version` |
| `402 Payment Required` / private scoped | 当私有包发了 | 加 `--access public` 或 `publishConfig.access` |
| `403` / not authorized | 无该 scope 权限 | 加入 Org 或改包名 |
| `ENEEDAUTH` | 未登录或 token 过期 | 重新 `npm login` |
| `EPUBLISHCONFLICT` | 并发/缓存冲突 | 确认版本未被占用后重试 |

## 8. 推荐的完整「升级发布」流水线（日常）

本地已有 `0.1.0` 之后，每次发新版按此顺序：

```bash
cd /path/to/ai-code

# 1. 确认登录与线上最新版
npm whoami
npm view @agent-xy/ai-code version

# 2. 测试
npm test

# 3. 升版本（按变更选 patch / minor / major）
npm version patch --no-git-tag-version

# 4. 预览产物
npm pack --dry-run

# 5. 发布
npm publish --access public

# 6. 验收
npm view @agent-xy/ai-code version
```

发布成功后建议：

1. 把版本变更与代码一并 commit（若尚未提交）  
2. 打 git tag，例如 `v0.1.1`，并 push：`git push && git push --tags`  
3. （可选）在 GitHub Releases 写变更说明  

> 仅当用户明确要求时再执行 commit / push；本文只规定发布顺序，不代替发版决策。

## 附录 A：registry 与镜像注意

本仓库 `publishConfig.registry` 指向官方源。若本机曾配置淘宝等镜像：

```bash
npm config get registry
```

发布时务必打到官方源。临时指定：

```bash
npm publish --access public --registry=https://registry.npmjs.org/
```

安装给国内用户可用镜像；**发布不要用镜像**。

## 附录 B：撤销发布（慎用）

- 发布后 **72 小时内** 可用 `npm unpublish <pkg>@<version>`（有限制，且对依赖者不友好）  
- 超过时限或已有依赖时，通常用 `npm deprecate` 标记废弃，而不是硬删  

```bash
npm deprecate @agent-xy/ai-code@0.1.0 "请升级到 0.1.1"
```

除非错误发布了密钥或严重问题，否则不要 unpublish。
