验证和发布 scoped 包（如 `@agent/ai-code`）需要按顺序进行权限核实、本地打包校验、登录授权和公开发布。以下是完整的逐步骤验证与执行指南：

1. **1. 验证 Scope 权限与包版本状态:** 发布前的网络与账号检查.
   运行以下命令核实账号权限和版本占用：

```bash
# 1. 确认当前终端登录的账号名称
npm whoami

# 2. 检查 @agent/ai-code 是否已发布以及存在的版本
npm view @agent/ai-code versions

```

- **判定结果与处理：**
- **无包/未发布：** 如果 `npm view` 返回 `404 Not Found`，说明该包尚未被创建或 `0.1.0` 版本未发布，可以继续。
- **版本已存在：** 如果返回列表中已包含 `0.1.0`，因 npm 不允许覆盖已发布版本，需修改 `package.json` 中的 `version`（例如改为 `0.1.1`）。
- **没有 Scope 权限：** 若你不是 `@agent` 组织（Org）的成员，无权发布到该命名空间。此时需在 `package.json` 中将 `"name"` 修改为未被占用的名称（如 `ai-code` 或 `@your-username/ai-code`），并同步修改 `README.md` 中的安装命令。

_验证方法：`npm view @agent/ai-code versions` 确认无 `0.1.0` 版本冲突。_

2. **2. 本地测试与消费者安装验证:** Node ≥ 18 环境.
   在发布前对产物完整性和运行逻辑进行二次验证：

```bash
# 1. 确认 Node 环境大于等于 18
node -v

# 2. 运行自动化测试
npm test

# 3. 预检打包包含的文件列表（不会真正生成文件）
npm pack --dry-run

```

检查 `--dry-run` 输出中的 **Tarball Contents**：确认 `dist/`、`package.json`、`README.md` 等必需文件包含在内，且排除了 `.env`、未编译源码、测试用例等敏感或多余文件。

**模拟消费者安装验证：**

```bash
# 打包出本地 tarball 压缩包（例如生成 agent-ai-code-0.1.0.tgz）
npm pack

# 切换到临时目录模拟真实项目安装
cd /tmp && mkdir test-app && cd test-app
npm init -y
npm install /包的绝对路径/agent-ai-code-0.1.0.tgz

# 编写简单代码验证 API 引入与执行
node -e "const pkg = require('@agent/ai-code'); console.log(pkg);"

```

_验证方法：模拟测试项目中能够正常 `import` 或 `require` 并成功运行逻辑。_

3. **3. 登录账号与发布前核对:** 账号授权验证.
   回到项目根目录，检查配置并完成账号授权：

1. **核查配置文件**：检查 `package.json` 中的 `main`、`module`、`types`、`files` 字段指向路径是否存在，确认 `README.md` 中的安装与导入示例准确无误。
1. **登录 npm**：

```bash
# 使用网页授权登录（推荐，避免终端 2FA 输入问题）
npm login --auth-type=web

# 校验当前登录的主体
npm whoami

```

_验证方法：`npm whoami` 返回的用户名具有 `@agent` scope 的写权限（或者就是 `@agent` 用户本身）。_

4. **4. 执行公开发布与产物验证:** 正式发布流程.
   npm 默认会将带 `@scope` 前缀的包作为私有包（Private）处理，公开发布时**必须显示指定 `--access public**`：

```bash
# 1. 执行公开发布
npm publish --access public

# 2. 验证线上已同步最新版本
npm view @agent/ai-code version

```

_验证方法：`npm view @agent/ai-code version` 正确输出 `0.1.0`，且通过 `npm i @agent/ai-code@0.1.0` 能够在线安装。_
