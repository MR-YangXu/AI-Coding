# AI Code

`@agent-xy/ai-code` 是面向 Vue 3 + Vite + TypeScript 的 AI 编码规范 npm 包。为 Cursor 提供一份短规则、八个通用技能及按项目选择的场景补充，并把项目现有质量检查统一为 `npm run ai:check`。源码与项目配置是技术事实来源；不需要填写任务档案或维护项目事实状态机。

## 一键接入

Node.js 18+，项目需要已有 `package.json` 及 Vue 3、Vite、TypeScript 依赖。执行：

```bash
npx @agent-xy/ai-code init
npm run ai:check
```

`init` 根据项目的 `packageManager` 字段或锁文件选择 npm、pnpm 或 yarn，安装确切版本的开发依赖，生成 `.cursor/rules/ai-code.mdc`、`.cursor/skills/ai-code-*/SKILL.md`、`.ai-code/config.json` 并添加 `ai:check` 脚本。对已经安装包的项目不会重复安装；离线验收可使用 `init --no-install`，之后仍需手动安装依赖才能运行 `npm run ai:check`。已有同名用户文件或脚本不会被覆盖。

Cursor 的基础规则默认加载；页面、组件、常量与字典、Hook、API、共享状态、路由和国际化技能按任务加载。CLI 决定项目安装哪些场景补充，AI 再根据当前任务选择相关技能。包中的 `content/` 是工具无关的唯一规范来源；`src/adapters/` 用于工具投影，后续可以在不改项目质量命令的情况下增加 Codex 适配器。当前未提供 Codex 投影。

## 按项目选择场景

首次在交互终端执行 `init` 时，可以输入编号选择场景，多个编号用逗号分隔，直接回车只安装通用规则。非交互环境、CI 或使用 `--json` 时不会询问，未指定场景则默认通用；已接入项目再次 `init` 会保留已有选择。

| 场景参数 | 安装内容 |
| --- | --- |
| `none` | 基础规则 + 八个通用技能 |
| `admin` | 通用内容 + 管理后台技能：复杂查询、表格、批量操作、权限与编辑流程 |
| `mobile-h5` | 通用内容 + 移动端 H5 技能：触摸、安全区域、软键盘、滚动、弱网与资源加载 |
| `admin,mobile-h5` | 通用内容 + 两类场景补充；按当前页面判断适用范围 |

通用层负责 Vue 数据流、组件与组合式函数边界、实例状态隔离、类型、异步资源和样式作用域，不预设页面文件树或 UI 库。后台的搜索与列配置、分页流程、详情抽屉和头像管理范例集中在 `admin`；移动端的触摸、安全区域、软键盘与滚动行为集中在 `mobile-h5`。

场景安装范围与任务适用范围分别判断：仅启用 H5 时不会生成后台技能；混合项目也只按当前功能选择，存在搜索、表单、列表或登录权限不足以判定为后台。移动端管理功能可以同时应用两个已启用的场景。

也可以直接指定，适用于脚本和自动化：

```bash
# 新项目接入管理后台场景
npx @agent-xy/ai-code init --scenarios admin

# 新项目只接入通用 Vue 与移动端 H5 能力
npx @agent-xy/ai-code init --scenarios mobile-h5

# 已接入项目改为同时启用后台与移动端
npx @agent-xy/ai-code sync --scenarios admin,mobile-h5

# 恢复为仅通用规则
npx @agent-xy/ai-code sync --scenarios none

# 查看选择与规则一致性
npx @agent-xy/ai-code status
```

选择保存在 `.ai-code/config.json` 的 `scenarios` 数组中；`--scenarios` 替换完整选择，`sync` 省略该参数则沿用已保存的值。没有此字段的旧配置按通用场景读取，下次同步时补齐。未知场景或无效参数会报错，不能静默退回默认。

同步会更新基础规则中的场景入口，并只安装所选场景的技能。取消选择时，只删除受控清单中未经手改的对应 `SKILL.md`，保留同目录用户文件；任何受控文件被修改、路径为符号链接或新文件与用户文件冲突时，先报错，不切换场景。项目类型由开发者选择，不通过组件库或目录名自动推断。

场景补充没有独立的质量命令，也不会自动引入移动端适配库、UI 库或新的构建框架；继续使用项目已有检查。查看全部命令可运行 `npx @agent-xy/ai-code --help`。

## 项目补充约定

团队在 `.ai-code/profile.md` 中维护本项目的推荐入口、参考页面及局部约定。npm 包提供三份独立模板，每份都包含填写说明、待填表格与示例，选择适合当前项目的一份：

| 适用项目 | 模板 | 主要填写内容 |
| --- | --- | --- |
| 通用 Vue | [profile.vue.md](content/templates/profile.vue.md) | 布局、基础组件、组合式函数、主题与局部组织约定。 |
| 管理后台 | [profile.admin.md](content/templates/profile.admin.md) | 搜索、表格、上传、抽屉、后台查询与操作能力及参考页。 |
| 移动端 H5 | [profile.mobile-h5.md](content/templates/profile.mobile-h5.md) | 移动适配、触摸、列表加载、滚动恢复、图片及实际需要的宿主能力。 |

完成依赖安装后，在业务项目根目录复制模板。以下以通用 Vue 为例；后台或 H5 将源文件名替换为对应模板名：

```bash
mkdir -p .ai-code
cp -n node_modules/@agent-xy/ai-code/content/templates/profile.vue.md .ai-code/profile.md
```

`cp -n` 保留已有文件。已经有 profile 时按需合并模板内容；混合项目从通用模板开始，合并适用场景的章节并写明对应模块范围。复制模板不会修改已启用场景；安装场景仍由 `init` 或 `sync --scenarios` 控制。

填写时先核实推荐组件和至少一个调用方，再替换“待填写”与示例路径；删除不适用的行、空章节和示例说明。未填写项不构成约定，不为凑齐表格虚构能力或新建组件。保留“适用范围、用途、源码入口、参考实现及借鉴边界”即可，不需要把每个公共文件都登记一遍。

该文件可选，`init` 和 `sync` 不创建、不覆盖它；不要在此重复 `package.json` 中的质量命令。生成的基础规则会提示 AI 在文件存在时读取。

首次接入、团队梳理约定或公共能力变化时再维护这份文件。每个推荐项写清适用范围、用途、源码入口和参考实现中可借鉴的部分，使用相对项目根目录的稳定路径。组件参数与事件仍读取源码；外部优秀页面只提供组织参考，不能成为当前项目不存在的导入来源。没有 profile 时先依据本项目同类实现继续工作并说明缺口。

## 页面生成与结构验收

项目准备与每次开发分开处理：推荐入口和质量命令在接入或发生变化时维护；每次开发执行“明确范围 → 读取约定与源码 → 决定复用 → 明确状态和交互预期 → 实现 → 质量检查与行为验收”。常规实现决策自主推进，不要求逐步审批或维护任务档案；小改动保持原有范围，不按行数或固定目录机械拆分。

复用有三种结果：能力满足时直接接入；核心交互匹配但存在小缺口时评估兼容扩展；交互不匹配或扩展会牵连无关调用方时就近实现。放弃已有能力时，在当前任务或代码审查说明中给出以下依据，不要求新增专门文件：

```text
需求：当前交互必须满足什么。
候选：组件或 Hook 的源码位置及已有调用方。
能力与缺口：哪些已满足，哪些参数、分支或事件不匹配。
扩展评估：配置、插槽或最小扩展是否足够，会影响哪些调用方。
决定：直接复用、兼容扩展或私有实现，以及对应验证项。
```

“更贴近设计稿”或“直接写更简单”不能单独说明能力缺口；没有示例调用也不能证明组件不支持。

`admin` 在通用能力上补充搜索与列配置、私有详情和卡片组件、页面样式的组织方式，以及头像卡片页、标准表格页和详情抽屉页的正反范例。这些内容不进入通用技能；H5 页面应用通用能力与移动端交互要求，按自身项目惯例组织代码。

范例不自带业务接口或项目组件；所有导入、字段和权限以目标仓库为准。接口缺失时继续完成不依赖它的工作，并明确待联调项，不能把演示交互写成业务功能已完成。

交付证据分为结构审查、实际交互验证和项目质量命令结果。`ai:check` 与增量诊断沿用既有检查机制，不会自动判断组件职责是否合理、数据是否符合业务口径，也不能证明 Cursor 实际执行了每条规范。更新包后运行 `ai-code sync` 可同步增强后的规则；仅修改本包源码不会改变已经接入项目的规则。

后台技能按需提供搜索、重置、标签切换、启停、图片失败及空态与统计的操作/预期表。每次只验收改动涉及的行为，注明自动测试、浏览器验证或模拟验证；没有运行和不适用分别说明。H5 继续使用移动端对应检查。模拟响应可以验证展示和失败恢复，真实接口持久化尚未验证时须单列为待联调。

## 质量检查

初始化会识别已存在的 `lint`、`typecheck`、`test`、`build` 等别名，写入 `.ai-code/config.json` 的 `scripts` 映射。不会安装或重写 ESLint、Vitest、Vite、TypeScript 的配置。`--fix` 与交互式测试脚本不作为自动检查；可在项目中新增非交互、非修改型脚本后更新映射。

```bash
npx @agent-xy/ai-code status
npm run ai:check -- --json
npx @agent-xy/ai-code sync
```

- `status` 仅读取项目，不运行检查。`status` 和 `check` 都展示场景选择并检查与受控文件是否一致；`check` 还执行配置的质量命令并检查包版本。
- 默认 `observe`（观察）模式：缺失检查显示 `missing`，不阻断；已有命令失败、规则漂移和无效配置仍阻断。
- 修改 `.ai-code/config.json` 的 `mode` 为 `enforce`（阻断）后，缺少 lint、typecheck 或 build 也会阻断；test 暂不列为所有项目的强制项。
- npm 包升级后执行 `npx @agent-xy/ai-code sync`；有手工改动的受控文件会拒绝覆盖。团队定制内容请放入其他 Cursor 文件。`status` 和 `check` 支持 `--json`。

建议先在项目内执行 `status` 了解缺口，再为当前项目补齐合适的检查脚本。规范无法独自验证业务需求；关键交互还需要对应测试与人工代码审查。

### 类型检查缺失或失效时

1. 复现错误，区分检查配置、历史类型错误和新增错误；核对应用、构建脚本、全局声明及生成类型的检查边界，保留应检查的 Vue、TS 和 TSX 文件。
2. 在项目 `package.json` 中维护独立的类型检查脚本，例如 `"typecheck": "vue-tsc --noEmit"`；实际参数以项目配置为准，不能将示例当作所有项目的修复方案。
3. 显式将 `.ai-code/config.json` 中的 `scripts.typecheck` 设置为该脚本名，例如 `"typecheck"`，保留其余映射。当前 `sync` 不会重新识别新增命令，重复 `init` 也不会重建已有映射。
4. 先运行类型检查脚本，再通过 `ai:check` 确认它实际执行。修复检查配置时，可在临时副本中放入一个已知类型错误验证覆盖范围，恢复后再次确认正常结果。

类型检查、ESLint 与构建分别报告结果；Vite 构建成功不能证明类型检查通过。历史问题未解决时保留失败状态，同时推进不依赖它的工作；不能通过排除业务目录、增加 `any` 或忽略错误来制造通过。npm 包继续使用项目检查体系，不统一覆盖 TypeScript 配置，也不因选择某个场景自动切换阻断模式。

## 常量与数据字典

常量技能是通用能力，普通 Vue、后台和 H5 都适用。基础规则提供固定入口：涉及常量时按“公共导出 → 当前业务入口 → 相关定义”检索。会话中已核实且未变化的内容直接复用；文件变化、业务切换或上下文缺失时补读必要片段。新增前定向检索全项目，不每轮全文加载目录。

**同一业务语义只能定义一次。** 公共定义以 `src/constants/common.ts` 为默认位置，通过 `src/constants/index.ts` 导出；业务定义跟随模块的 `constants.ts`。页面、组件、Hook、API 和页面配置统一导入，禁止同名重建、换名复制，或在公共与业务两处维护同一事实。转导出、导入别名及从权威定义派生选项允许存在；不同业务仅数字相同不能强行合并。

码值采用 `as const` 对象或显式赋值的 TypeScript 枚举；字典键引用成员，选项从常量与字典派生。保留接口码值类型，不让数字选项变成字符串。动态字典仍来自 API 或已有字典能力；国际化项目保存翻译键并响应式生成展示文案。

### 可复制示例

安装包 [content/templates/constants/](content/templates/constants/) 提供一组完整示例：

| 示例文件 | 示例目标位置 |
| --- | --- |
| `common.ts`、`index.ts` | `src/constants/` 下同名文件 |
| `business.constants.ts` | `src/views/orders/constants.ts` |
| `usage.vue` | `src/views/orders/index.vue`，演示导入、默认值、重置与选项 |
| `config.json` | 仅将 `constants` 节合并到项目已有 `.ai-code/config.json`，保留其余配置 |

这些是示意订单业务，复制前替换路径与契约，不覆盖已有定义。示例使用项目常见的 `@/*` 别名；检查器读取项目 `tsconfig.json` 的 `baseUrl`、`paths`，实际别名位于其他配置时通过 `constants.tsconfig` 指定，或者使用相对导入。`init`、`sync` 不自动复制示例或开启业务扫描；`sync` 保留项目自行维护的 `constants` 配置。

### 配置与扫描范围

配置结构见 [config.json](content/templates/constants/config.json)。所有路径相对项目根目录，配置只登记归属与引用关系，不重复登记码值或文案：

| 字段 | 约定 |
| --- | --- |
| `common.entry` / `common.files` | 可选公共导出入口与实际定义文件；登记公共定义时必须提供。 |
| `definitions` | 每项用唯一 `id` 表示业务语义；`owner` 为 `common` 或业务模块 ID，`file` 与 `export` 指向唯一定义；`dictionary` 可选，指向同文件的字典导出。单值常量不配置字典。 |
| `modules` | 每项声明唯一 `id`、`include`、可选 `exclude` 和 `bindings`。匹配支持 `*`、`**`、`?`，不支持花括号；多种路径拆成数组项。 |
| `bindings[].definition` | 引用已登记语义 ID；只能绑定本模块或公共定义。 |
| `bindings[].fields` | `status` 匹配该范围内所有同名字段、变量及 `.value`；`query.status` 只匹配指定访问路径。不同语义的同名字段应细化绑定或拆分模块范围。 |
| `bindings[].options` | 本模块选项变量名，例如 `statusOptions`；检查其声明内部的 `value`。 |
| `bindings[].template` | 用 `component`、`prop` 指定模板属性，可选 `model` 限定当前元素或祖先的 `v-model` 表达式；组件名和表达式按源码填写。 |
| `tsconfig` | 可选的别名配置文件路径，默认读取存在的根 `tsconfig.json`。 |

检查器使用包内 TypeScript 与 Vue 官方解析器，不改写项目 ESLint、TypeScript 配置。仅实际扫描时加载解析器；未配置的旧项目与 `status` 不扫描源码。默认跳过 `node_modules`、`.git`、`.ai-code`、`.cursor`、`dist`、`coverage` 及符号链接目录；登记定义不能通过符号链接逃出项目。

### 检查结果与边界

运行 `npm run ai:check` 后，结果中新增 `checks.constants`。检查对象是配置范围及登记的公共文件：字段赋值、默认值、比较、分支、数组成员判断、静态选项和 Vue 模板绑定中的硬编码；常量来源、重复定义、静态字典键及覆盖情况。普通计数、数组下标和布局数字不纳入业务硬编码检查。

- 同一语义 ID 不能登记多个位置，同一位置不能重复登记；模块内重新声明已登记常量或字典属于确定违规。改名后成员名及码值一致的静态对象属于疑似重复，只提示核对，不因数值相同自动合并业务。已明确登记为其他业务语义的定义不作为复制处理。
- 支持命名导入、命名空间导入、导入别名、静态局部常量别名及转导出；使用处仍须从指定的公共入口或业务定义导入。`null`、`undefined` 可表示未选择，业务码值与其他筛选哨兵值须使用常量。
- 只对可静态确认的源码作结论，不追踪任意函数返回值、运行时赋值或所有跨文件数据流；疑似重复需要结合契约审查。未经绑定的业务字段不会自动猜测归属，这些边界不放宽禁止硬编码与重复定义的规范。
- 登记枚举支持数字/字符串字面量对象和显式赋值枚举；静态字典必须直接声明计算键，不使用展开或运行时函数生成字典本体。动态字典不登记为静态字典；其固定 code 可登记为单值常量。外置 Vue 脚本/模板或其他模板预处理语言会报告检查未完成。
- 文本和 JSON 均提供总数、确定违规数、疑似重复数和最多五条定位信息，优先保留确定违规；处理已列问题后重查。扫描只读，不自动改写、合并或删除源码。

| 结果 | 行为 |
| --- | --- |
| 未配置 `constants` | `not_configured`，不阻断旧项目，也不称为通过。 |
| `status` 且配置有效 | `available`，只校验配置结构，不扫描。 |
| 已完成且无问题 | `passed`。 |
| 观察模式发现违规 | `warning`，保留违规明细，不因常量违规阻断。 |
| 阻断模式发现确定违规 | `failed`，退出码 1。只有疑似重复时仍为 `warning`。 |
| 无效配置、冲突、范围无文件、定义或语法无法解析 | `incomplete`，两种模式均退出码 1，不能冒充通过。 |

上述模式区别仅适用于新增常量检查；已有 lint、类型检查、测试、构建命令失败仍按原有规则阻断。静态检查不能证明模型实际执行了读取顺序或理解了业务语义。

## 可选的增量诊断

已安装项目依赖且有本地 ESLint 的 Git 工作区可在开发中运行：

```bash
npx @agent-xy/ai-code quality inspect
npx @agent-xy/ai-code quality inspect --json
```

`inspect` 将相对 `HEAD` 已暂存、未暂存和未跟踪的 Vue/JS/TS 文件按当前工作区内容交给项目 ESLint 检查，并用 `HEAD` 内容计算历史诊断基线。不会自动修复源码或写入诊断日志；默认只显示前五条新增诊断、总数和是否截断。新增诊断返回 `failed`（退出码 1）；Git、基线或 ESLint 无法可靠检查时返回 `incomplete`（退出码 1），不得视为通过；没有适用改动时返回 `skipped`。本命令不需要也不会修改 `.ai-code/config.json`。

增量指纹结合路径、严重程度、规则和消息，并参考 Git 新增行处理同文件同名错误与重命名；它仍是近似诊断，不能证明没有新问题。基线使用当前安装的 ESLint 与配置；规则/配置变更、跨文件依赖及类型错误需要通过原有的 `ai-code check`、适用测试和人工审查验证。暂不提供自动 `fix`、严格暂存区检查或审计报告。

## Jenkins 共享流水线

公司平台在项目安装依赖后检测 `package.json` 是否声明 `ai:check`，有则执行 `npm run ai:check`（pnpm/yarn 使用对应的 `run ai:check`）。无需写入每个项目的 Jenkinsfile。流水线以退出码判定结果；观察模式的 `missing` 是能力缺口，不得展示成通过。若需要纯 JSON 报告，可在使用 npm 或 pnpm 的项目直接执行 `./node_modules/.bin/ai-code check --json`，或使用包管理器对应的命令入口。`npm run ai:check -- --json` 会带 npm 横幅，不能把整段输出直接解析为 JSON。
